# 工具可用性检查

在“工具调用”或更多菜单中打开“工具可用性检查”。它按所选任务读取 MCP 服务状态与工具目录，每 30 秒更新，也可手动重查。检查本身不执行工具、不重载插件、不恢复旧任务。

| 结果 | 含义 |
| --- | --- |
| 目录已登记 | 所属服务连接正常、目录完整，并包含对应工具名 |
| 目录未提供 | 所属服务连接正常且目录完整，但未包含对应工具名 |
| 未见所属服务 | 完整列表里没有对应服务，不能据此区分未启用与未加载 |
| 未验证 | 断线、数据过期、任务未加载、请求失败或目录不完整 |

`read_thread` 使用完整名称匹配，`read_thread_terminal` 不作为替代。只有明确的服务失败状态触发 Critical；目录减少仅作中性变化提示，也可能是用户调整插件设置造成的。

页面保留最近目录读取时间，以及本次监视期间确认的重新登记／重新连接记录。未知数据不会被当成恢复，断线前迟到的结果会被丢弃。工具列表限制高度，刷新时保留用户的展开选择。

## 实现与限制

通过客户端的只读 `mcpServerStatus/list` 接口，按所选 `threadId` 分页读取，并设置超时。仅获取服务名、状态枚举、目录完整性和工具名，不导出工具定义、资源正文或凭据。参考：[App server 文档](https://learn.chatgpt.com/docs/app-server)。

目录已登记不证明工具执行成功，也不证明模型在某一轮最终收到的定义。内置非 MCP 工具不在这个目录中。历史监视记录只在内存中保留有限数量，不构成完整故障审计。

隔离测试覆盖分页、目录变化、服务失败、断线迟到响应、会话替换、错误目录格式和重新登记；检查独立执行，不阻塞普通状态采样。
